# 角色渲染与动作优化 · 第一轮待验收

本分支仅调整客户端表现层，保留原始加密模型、贴图、语音和版权信息。不改棋力、规则、落子时长或计时归属，不合并、不自动发布。

## 已实现

- 脸、身体、眼睛使用不同 shader cache key，防止相同回调文本导致错误复用边缘光强度。
- 描线从模型单位厚度改为约 0.85 CSS 像素；面部更细。描线在蒙皮后计算，并使用当前 renderer / render target 的尺寸，兼容主画面和头像。
- 描线保留贴图透明裁切，不再给透明发片的整块三角面画边；共享原骨骼与 morph，不复制模型。
- 手势目标与最终姿态分离，指数平滑接续被打断的动作；头部追踪改为与帧率无关的平滑。进入拿子时保存当前四肢姿态，逐渐过渡到 IK，避免直接跳回坐姿。
- 元音口型交叉淡入淡出；音频当前为静音时闭嘴，不再意外回退文字口型。
- 拿子路径及握指曲线缓入缓出，弧线端点速度归零；走子各阶段时长和落子/解锁时机不变。
- 头像曝光与主画面一致，尺寸变化时更新投影；省电模式同时限制头像像素比。

## 2026-10-20 运行时反馈与兼容补丁

首次真实模型外部 QA 曾怀疑候选 `96979e9` 待机/思考静止及背影尺寸改变；当时镜头缩放未完全对齐、截图间隔较长。后续复测已撤销这两项回归判断，见下节。

已增加生产 `Board3D._loop` → `onFrame` → `LemalinMMD.update` 与真实 `THREE.Clock` 的回归，渲染端用替身；新建候选实例会正常推进待机、思考、隐藏后恢复及长帧暂停。本地另复现：若预览保留已解锁的旧角色实例、只替换新方法，缺少新增 `smoothPose` / `mouthWeights` 会每帧抛错，棋盘继续而角色冻结。兼容补丁按需初始化这些新增状态，并避免依赖 `structuredClone`。此路径补丁前失败、补丁后通过。

**兼容修复不是对外部 QA 现场根因的确认。** 后续确认外部测试是完整新实例，并没有热替换，因此不能宣称该兼容补丁修好了现场冻结。完整 GPU 与真实模型验证仍按上方清单执行。不要求读取密码、浏览器存储或明文模型。
